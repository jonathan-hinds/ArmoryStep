# OneBit Adventure behavior checklist

Checked 2026-08-03 against current official pages, update notes, official 2024 footage, and mobile gameplay footage.

- [x] Character cards are the main selection surface; creation chooses a class/name, while a saved card becomes **Resume Adventure**.
- [x] The game is portrait, one-handed, and presents a narrow world that procedurally continues upward; downward travel is screen-limited.
- [x] Movement is cardinal and grid-based. Moving toward an adjacent enemy attacks without entering its tile.
- [x] Player move/attack/wait actions advance enemies. Enemies do not run in real time between player turns.
- [x] Touch/click drag moves or attacks; touch/click without a meaningful drag waits. Keyboard uses WASD and Space as a secondary PC/Web option.
- [x] Distance is associated with adventuring upward, not every combat/menu action.
- [x] Kills grant XP; levels and character stats persist beyond an individual adventure.
- [x] The first campfire is at 100 steps. Campfires support saving a resumable adventure; the character card then advertises Resume Adventure.
- [x] Death ends the active adventure while character progression remains. A bonfire is not treated as an automatic death respawn in this foundation.
- [x] The requested five-slot carousel, exact **Save and Go Home** action, and floating joystick behavior are product-scope requirements for OneStep.

Not inferred: OneBit's private tile resolution, generation formula, complete enemy AI, loot/equipment economy, revive economy, leaderboard submission, Quick Save limits, or modern class roster. The project uses a documented nine-column placeholder grid and three intentionally simple enemies.
